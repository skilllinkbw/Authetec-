# AutheTec — Benchmark Report

**Date:** 2026-09-03

## Accuracy policy

Every metric below states **what it was measured on**. Nothing in this
report may be quoted as real-world accuracy without its measurement
context. Benchmark classes used:

- **SYNTHETIC** — data generated by the harness itself.
- **Internal** — Authetec's own test fixtures.
- (Research / Production validation benchmarks: **not yet performed** —
  explicitly reported as gaps rather than estimated.)

## 1. Face verification — SYNTHETIC

Harness: `python -m benchmarks.face.run_face_benchmark` (reproducible: fixed
seed, fixed projection matrix, full dataset description in each report).
Reports: `benchmarks/reports/Face_Verification_Synthetic_*.json/.md`.

Measured on the synthetic Gaussian-identity dataset (120 identities,
2,400 genuine + 2,400 impostor pairs, 64-d embeddings, seed 7):

| Metric | Value | Context |
|---|---|---|
| ROC-AUC | 1.0 | SYNTHETIC clusters are well-separated by construction; perfect separation is a property of the generator, **not** evidence of real-world performance |
| EER | 0.0 @ threshold 0.42 | same caveat |
| FAR @ 0.62 | 0.0 | same caveat |
| FRR @ 0.62 | 0.0 | same caveat |
| Precision / Recall / F1 | 1.0 / 1.0 / 1.0 | same caveat |
| Similarity latency | ~0.0002 ms (64-d cosine) | 2,000-iteration mean |

**Purpose of this run:** demonstrate that the matching pipeline, threshold
sweep and FAR/FRR machinery work and are reproducible. During harness
development it also caught a real calibration bug (intra-cluster noise
dominating unit-length centers → FRR ≈ 100%), which was fixed before
finalising.

**Not measured (gaps, deliberately not fabricated):**

- Real-face verification accuracy (requires labelled dataset, e.g. LFW for
  research context, with a production embedder).
- Liveness / presentation-attack detection performance (requires PAD
  hardware/software and attack datasets).
- OCR field-extraction accuracy and tamper-detection rates (require labelled
  document datasets).

## 2. Transaction fraud — existing adapters (SYNTHETIC)

Pre-existing adapters under `benchmarks/adapters/` (LightGBM, ensemble,
random-forest pipeline, insurance, graph surrogate, identity duplicate) run
on synthetic samples via `python -m benchmarks.run_benchmarks --all`.
Latest recorded results: `benchmarks/reports/summary.json` (generated
2026-08-30). These are SYNTHETIC-context runs used to validate the adapter
plumbing; no real fraud dataset has been evaluated yet.
